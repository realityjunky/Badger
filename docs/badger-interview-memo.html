  1. §1Overview: four planes概览：四个平面

    “I explain the system as four cooperating planes. Skills and Creator form the instruction plane; Workflow Protocol forms the semantic contract plane; WorkflowRuntime plus Engine form the runtime/control plane; and identities, artifacts, trajectories, receipts, evaluations, and readiness form the evidence plane. The planes have different owners, so an Agent can contribute work without becoming the authority for routing or durable state.”

    “我把系统解释成四个协作平面。Skill 和 Creator 形成说明平面；Workflow Protocol 形成语义契约平面；WorkflowRuntime 加 Engine 形成 Runtime/控制平面；身份、产物、轨迹、回执、评估和 readiness 形成证据平面。每个平面有不同的拥有者，所以 Agent 可以贡献工作，却不会成为路由或持久化状态的权威。”

  2. §1.1How Badger worksBadger 如何工作

    “At the highest level, Badger is a governed package factory plus a durable execution product. Creator/Factory owns meaning and delivery evidence; WorkflowRuntime owns each Run; the host performs external work. The immutable package snapshot and execution identity are the handoff. Only the runtime can accept an outcome and move the Run, while evidence connects that execution to evaluation, readiness, approval, and delivery.”

    “在最高层，我把 Badger 解释成一个受治理的软件包工厂和持久化执行产品。Creator/Factory 拥有工作流含义与交付证据；WorkflowRuntime 拥有每个 Run；宿主执行外部工作。不可变软件包快照和执行身份是两者之间的交接，证据则把执行连接到评估、readiness、批准和交付。”

  3. §1–5Abstraction layers抽象层级

    “I explain the five levels as zoom, not as five different systems. Ecosystem asks who participates; package asks what is declared; Run asks what is persisted; transition asks how one turn is guarded; and module asks where the boundary lives in code. The vocabulary changes at each zoom, but package identity, pending action, validation, continuation, and one runtime authority remain invariant.”

    “我把五个层次当作缩放，而不是五个不同的系统。生态层问谁参与；软件包层问执行前声明了什么；Run 层问什么被持久化；转换层问一次回合如何受保护；模块层问边界在代码中的什么位置。词汇会变，但软件包身份、Pending action、校验边界、continuation 和单一 Runtime 权威保持不变。”

  4. §5.2Inside WorkflowRuntimeWorkflowRuntime 内部

    “The key module decision is one runtime authority. Callers see start, resume, submit, and recover; private capabilities compile, route, validate, persist, and project behind that seam. Generated scripts preserve compatibility but delegate to WorkflowRuntime, so no second state machine can drift from the Engine-backed Run.”

    “最重要的模块决策是只有一个 Runtime 权威。调用方只看到 start、resume、submit 和 recover；Compiler、Resolver、完成校验、决策作用域、产物版本、Run 位置、受保护存储和投影都留在内部。生成脚本保留兼容性但委托给 WorkflowRuntime，因此不会出现两套漂移的状态机。”

  5. §2.4Primer Designer instancePrimer Designer 实例

    “Primer Designer is a domain contract over the generic runtime. It keeps genome-download, primer-design, and primer-pool-add independent, then declares the Nodes, schemas, routes, review choices, and Cycle policy that compose them. WorkflowRuntime supplies identity, persistence, validation, routing, and recovery; the domain contract supplies the biological meaning and acceptance criteria.”

    “Primer Designer 是通用 Runtime 之上的领域契约。它保持 genome-download、primer-design 和 primer-pool-add 独立，并声明 Node、Schema、路由、审查选择和 Cycle 策略。Runtime 提供身份、持久化、校验、路由和恢复；契约提供生物学含义与接受标准。”

  6. §1.3When Badger fits适用场景

    “I position Skill Harness by the control boundary, not by a maturity ladder. Use it when the legal route, acceptance evidence, and recovery identity can be declared, while the work inside a Node may remain agentic. The protocol names the allowed graph; WorkflowRuntime proposes and accepts actions; an external worker performs them. That buys explicit decisions, immutable provenance, and fresh-process recovery at the cost of some autonomy and authoring simplicity. Primer Designer is a good fit because its cycles and review boundaries are knowable even though its scientific work remains external.”

    “我根据控制边界来定位 Skill Harness，而不是把它当作成熟度阶梯。只要合法路由、接受证据和恢复身份可以声明，Node 内部就仍可以使用 Agent。Protocol 声明允许的图；WorkflowRuntime 提出并接受动作；外部工作者执行动作。这样以部分自主性和创作简洁性为代价，换来显式决策、不可变来源追踪和新进程恢复。Primer Designer 很适合这个位置，因为它的 Cycle 和审查边界可知，而科学工作仍然在 Runtime 外部。”

  7. §3–4Lifecycle生命周期

    “A Run is an exchange between a deterministic runtime and an external executor. The runtime proposes one pending action, the executor performs it, and the host submits a result. Completion validation and identity checks happen before the Run mutates. If the process stops, a new process reads the persisted state and reconstructs the same continuation. For a decision Node, the pending action becomes an authorized waiting state rather than an informal instruction.”

    “我把生命周期分成创作、软件包和 Run 三个阶段。Authoring 先把来源和意图变成经过审查的语义内容；Factory 再组装软件包并用当前哈希证据决定它是否 ready；Runtime 最后从不可变快照创建 Run。每个 Run 回合都是提出 Pending action、在外部执行、提交并校验、再解析 continuation。创作状态与 Run 状态分别恢复，任何一方都不依赖聊天记忆。”

  8. §6Parameters and enums参数与枚举

    “I choose a parameter by asking which boundary it controls. Plan fields define meaning and dependencies; CLI flags define confirmation, identity, and destination; runtime fields bind one submission to one pending action and revision. The enums are not decoration: Node kind explains responsibility, enforcement explains whether evidence blocks progress, and the continuation disposition tells the host exactly what it may do next.”

    “我通过它控制的边界来选择参数。计划字段定义含义和依赖；CLI 标志定义确认、身份和目标；Runtime 字段把一次提交绑定到一个 Pending action 和 revision。枚举不是装饰：Node kind 解释职责，enforcement 解释证据是否会阻塞，continuation disposition 则准确告诉宿主下一步可以做什么。”

  9. §5Codebase map代码地图

    “I understand Badger as a layered standalone product. The CLI enters the workflow-kernel foundation, which discovers Skills and normalizes a workflow contract. The factory generates a package; Skill Runtime validates and snapshots it; Engine supplies generic durable Run mechanics; and WorkflowRuntime is the single authority that compiles, routes, validates, persists, and recovers. Evaluation and differential harnesses bind behavior to hashes and baselines, while publication is gated by current evidence and reviewer approval. When I debug it, I follow that dependency direction and verify the corresponding persisted record and focused test.”

    “我把 Badger 理解成分层的独立产品。CLI 进入 workflow-kernel foundation，它发现 Skill 并规范化工作流契约。Factory 生成软件包；Skill Runtime 校验并制作快照；Engine 提供通用持久化 Run 机制；WorkflowRuntime 是唯一负责编译、路由、校验、持久化和恢复的权威。评估和差分 Harness 把行为绑定到哈希和基线，发布则由当前证据与审查者批准门控。调试时，我沿这条依赖方向走，并核对相应的持久化记录和聚焦测试。”

Interview practice: the short explanations面试练习：简短解释

These are compact answers to common architecture questions. Expand them with the architecture diagrams in Section 1 and Section 5 of the manual when the interviewer asks for detail.

下面是常见架构问题的简短回答。面试官要求展开时，可以用手册第 1 节和第 5 节的架构图来补充。

What problem does it solve?它解决什么问题？

It turns loosely interpreted Skills into governed, authorable, resumable workflow packages and instances. The system keeps human-readable instructions while adding explicit authoring evidence, runtime state, contracts, and safe transitions.

它把松散解释的 Skill 变成可创作、受治理、可恢复的工作流软件包与实例。系统保留人类可读说明，同时增加显式创作证据、Runtime 状态、契约和安全转换。

Why not just use Markdown?为什么不只用 Markdown？

Markdown is excellent for method and progressive disclosure, but it does not by itself provide durable pending actions, stale-response rejection, route determinism, artifact provenance, or recovery after a process exits.

Markdown 很适合表达方法和渐进式披露，但单靠它无法提供持久 Pending action、过期响应拒绝、确定性路由、产物来源追踪或进程退出后的恢复。

Why not build a full Agent?为什么不直接构建完整 Agent？

The project does not need open-ended autonomy everywhere. It needs bounded, explainable domain workflows. Limiting the runtime’s authority makes certification, review, recovery, and distribution practical.

项目不需要处处开放式自主，而需要有边界且可解释的领域工作流。限制 Runtime 权威范围，使认证、审查、恢复和分发变得可行。

What is the most important design decision?最重要的设计决策是什么？

Two explicit authorities with different jobs: Authoring owns package content and lane evidence; WorkflowRuntime and Engine own generated-workflow routing, recovery, and committed Run state. Generated adapters remain projections.

两个职责明确的权威：Authoring 拥有软件包内容与 lane 证据；WorkflowRuntime 和 Engine 拥有生成工作流的路由、恢复与已提交 Run 状态。生成适配器仍然只是投影。

What makes it durable?什么让它具有持久性？

Run state and pending actions are persisted, identity-bound, and recoverable outside the original process. Badger also certifies journals, locks, checkpoints, receipts, snapshots, repair policy, and transactional finalization; authoring evidence remains a separate package-construction concern.

Run 状态和 Pending action 被持久化、绑定身份，并可在原始进程之外恢复。Badger 还认证日志、锁、检查点、回执、快照、修复策略和事务式终结；authoring 证据则单独支持软件包构建。

What makes Primer Designer a good example?为什么 Primer Designer 是好例子？

It has independent Skills, conditional route choices, optional stages, expensive evidence-producing steps, human review boundaries, and repeated design/pool cycles—exactly where a contract and durable runtime add value.

它有独立 Skill、条件路由、可选阶段、昂贵的证据产出步骤、人工审查边界和重复的 design/pool Cycle，正好体现契约与持久 Runtime 的价值。

Closing line结束语

“The project is not trying to eliminate probabilistic behavior. It is trying to put probabilistic behavior in the right place. An Agent can reason within a Node and use the allowed Skill or tools, but the workflow contract and runtime decide the boundaries: current action, required evidence, legal transition, durable identity, and recovery state.”

“这个项目并不是要消除概率性行为，而是要把它放在正确的位置。Agent 可以在 Node 内推理并使用允许的 Skill 或工具，但工作流契约和 Runtime 决定边界：当前动作、必需证据、合法转换、持久身份和恢复状态。”
