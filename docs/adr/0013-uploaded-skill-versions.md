# Uploaded Skill Versions Bind Files and Declarations to One Source Identity

Status: accepted. Uploaded Skill versions use the kernel's source identity and inventory, including its fixed ignore rules (ADR 0008). Files are stored by SHA-256 through a blob-store port, with a filesystem adapter first. A version's inventory and script side-effect declarations are immutable together. An identical upload returns the existing version; the same content with different declarations is a conflict. This preserves the one source identity used by the kernel rather than inventing a second version hash for service metadata. Correcting declarations therefore requires changed source content, such as documenting the corrected effects in the Skill itself.

Uploads are inspected in a fresh, private workspace through the kernel's source check. The service validates paths and resource limits first, rejects all links and special files, never executes uploaded code, and removes inspection workspaces after success or failure. An optional enclosing folder is removed before inspection. Ignored files are inspected for upload safety but are neither stored nor recorded in the immutable inventory. Previews return bounded text in JSON, so uploaded HTML and scripts are displayed as source.

Skill entries belong to Groups. Group leads manage entries; Engineers and Field experts may create entries and upload versions in the exact Group of a workflow where they hold that role. Every workflow role can read that Group's Skill library. Group membership continues to grant inherited read access, and Administrators and Auditors retain organization-wide visibility. A Group lead needs an Engineer or Field expert assignment to upload; Administrators may upload everywhere.

Upload rights come from the workflow role bindings of ADR 0012, so the binding that puts a Field expert on a workflow's team is the one that lets them upload. Separate Skill contributor roles were considered and rejected because they would duplicate the workflow authorization model.
