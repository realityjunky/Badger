# Uploaded Skill Versions Bind Files and Declarations to One Source Identity

Status: accepted. Uploaded Skill versions use the kernel's source identity and inventory, including its fixed ignore rules (ADR 0008). Files are stored by SHA-256 through a blob-store port, with a filesystem adapter first. A version's inventory and script side-effect declarations are immutable together. Because they cannot be added later, every script must be declared before a version is created, and `none` is a declaration; the kernel still reports an undeclared script, and a preview shows it, but no version stores one. An identical upload returns the existing version; the same content with different declarations is a conflict. This preserves the one source identity used by the kernel rather than inventing a second version hash for service metadata. Correcting declarations therefore requires changed source content, such as documenting the corrected effects in the Skill itself.

A confirmation names the previewed source by its hash (`expectedHash`), and the service requires it: content that no longer has that hash is a conflict that returns the computed hash, so a person signs off on the exact tree they reviewed (ADR 0005).

Uploads are inspected in a fresh, private workspace through the kernel's source check. The service validates paths and resource limits first, rejects all links and special files, never executes uploaded code, and removes inspection workspaces after success or failure. Names stay byte-exact, without Unicode normalization or separator translation, so the version hash is the kernel's identity of the original tree. Names are refused rather than rewritten when they contain backslashes, exceed 255 bytes in one segment, or would collide with another after NFC normalization and case folding, as they would on a normalization- or case-insensitive file system. Zip entry names must be UTF-8, by the UTF-8 flag or an Info-ZIP Unicode Path field, because a legacy code page could only be guessed. The `__MACOSX/` folder macOS Archive Utility adds is dropped before the optional enclosing folder is removed. Ignored files are inspected for upload safety but are neither stored nor recorded in the immutable inventory. Previews return bounded text in JSON, so uploaded HTML and scripts are displayed as source.

The filesystem blob store syncs each blob before linking it into its address and then syncs the directory, so a version committed after its blobs never names one a crash could leave torn. A file already at an address is trusted only if its bytes still hash to that address; otherwise it is replaced atomically.

Skill entries belong to Groups. Group leads manage entries; Engineers and Field experts may create entries and upload versions in the exact Group of a workflow where they hold that role. Every workflow role can read that Group's Skill library. Group membership continues to grant inherited read access, and Administrators and Auditors retain organization-wide visibility. A Group lead needs an Engineer or Field expert assignment to upload; Administrators may upload everywhere.

Upload rights come from the workflow role bindings of ADR 0012, so the binding that puts a Field expert on a workflow's team is the one that lets them upload. Separate Skill contributor roles were considered and rejected because they would duplicate the workflow authorization model.
